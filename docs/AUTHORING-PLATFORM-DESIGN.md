# PLATFORM-2 · StoryForge 创作平台、可见数据与模式层级

> 状态：ARCHITECTURE ACCEPTED；AGENT/FLOW CORE + SIM-1A IMPLEMENTED（2026-07-27）
> 施工归属：PLATFORM-2 / AGENT-1 / FLOW-2
> 用户原始要求：分步骤与节点是可切换创作模式；Agent 是覆盖其上的总入口；
> 后续跑团、文字游戏、角色聊天冒险在同一创作基座上形成独立体验。

## 1. 产品层级

```text
StoryForge
├── 项目中心（项目 = 统一故事世界与 Canon 数据容器）
│   ├── 分步骤模式（面板 / 标签页 / 人工逐项控制）
│   ├── 节点模式（自由上下文与创作数据流）
│   └── Agent 副驾（覆盖两种创作模式的单一总对话入口）
└── 体验中心（读取同一项目基座，拥有独立运行存档）
    ├── 跑团
    ├── 文字游戏
    └── 角色聊天冒险
```

项目不能在创建时被永久划分成“分步骤项目”或“节点项目”。两种创作模式是同一项目数据
的不同视图，作者可随时切换。Agent 不是第三种项目类型，而是覆盖两种创作模式的自然语言
编排层。体验类产品不得复制世界观、角色、物品或 Canon，只保存自己的局面、会话与事件。

## 2. 五层本地数据

### 2.1 Canon 正式数据

作者已经确认的世界观、故事核心、角色、关系、章节、物品、事实等继续以 IndexedDB
业务表为唯一真相。读取走 `CONTEXT_SOURCES + assembleContext()`，AI 写回走
`FIELD_REGISTRY + AdoptionSchema + adopt()`，生命周期走 `PROJECT_TABLES`。

### 2.2 创作过程数据

新增两组项目级、可导出的创作过程记录：

- Agent：`agentConversations` + `agentEvents`，保存用户消息、主 Agent 计划、领域任务、
  实际输入来源、候选、确认、拒绝、错误与用量摘要。
- 节点：`nodeFlows` + `nodeRuns`，保存自由图、节点参数、动态端口、连接、视口、输入快照、
  中间输出、最终候选与确认状态。

未确认候选不是 Canon，但必须可见、可恢复、可删除；刷新页面不能丢失。

### 2.3 检索派生层

现有 `retrievalChunks` / `narrativeSummaryNodes` 继续承担可重建检索缓存。扩展方向：

- 从“只索引章节正文”扩展为登记来源的统一 `RagDocument/RagChunk` 投影；
- 来源至少覆盖章节、世界观、角色、关系、物品、地点、历史、伏笔、作者选择的参考材料；
- 关键词检索默认本地零成本；embedding 是可选加速通道，不可成为唯一可用路径；
- 向量、摘要和关键词均为派生物，失效后从 Canon / 明确保存的资料重建，不反向覆盖正式数据。

### 2.4 可见检索管理层

新增“资料与检索库”视图，作者能够：

- 看见每个索引条目的来源、作用域、更新时间、文本摘要、分块数和向量状态；
- 启用/禁用某个来源，调整召回权重与 Token 上限；
- 查看一次 Agent/节点运行实际召回了哪些片段及其排序理由；
- 手动重建、删除派生索引；删除索引不删除原始作品；
- 把某次召回快照冻结进 Agent 事件或节点运行，保证结果可审计。

### 2.5 便携备份层

- Canon、Agent 会话/候选、节点图/运行产物、未来体验存档进入项目 JSON 备份。
- 可重建的 embedding 向量默认不导出，避免体积膨胀和模型不兼容；只导出来源配置、
  哈希与可选摘要，导入后重建。
- 所有新表必须先登记 `PROJECT_TABLES`，并通过项目删除、世界删除、导出导入和旧备份兼容测试。

## 3. Agent 模式

前台始终只有一条对话。主 Agent 负责意图识别、任务拆解、领域 Agent 调度、结果收敛和
确认卡片；领域 Agent 永不成为用户标签页。用户驱动写入必须确认，自主后台 Agent 默认只读。

主 Agent 团队角色可分别绑定已有 AI 连接预设，但角色选择只影响幕后模型/API 和上下文
预算，不改变唯一对话入口，也不允许模型绕过候选确认与正式 adoption。
五个领域的输入预算可独立设为精简、均衡或完整；实际 included / omitted / trimmed 来源、
估算 token 和上限随候选事件保存并在卡片中可见。
主 Agent、领域生成和一次 Canon 返工还共享节省/均衡/充分三档单轮总预算；预算在每次
调用前按冻结输入和最大输出预留硬阻断。GenerationNode gate 与可直接复用的零 token
Canon validator 可以携带具体证据把原领域打回一次，网络或软审错误不自动重试。

执行轨迹必须保存“用户原话 → 计划 → 分 Agent 输入来源 → 候选 → 确定性校验 → 用户决定”，
但默认只展示简洁进度，详细证据放在可折叠区域。

## 4. 自由节点模式

节点模式是独立创作工作台，不是 `PromptWorkflow` 的画布皮肤。路径自由等于上下文自由：

- 来源节点可选择具体项目元素、记录、字段、章节范围或自由文本；
- 连线声明数据流、目标槽位、优先级、强制/参考语义和 Token 上限；
- 创作节点可动态增加作者命名的输入端口；
- 处理节点负责筛选、合并、排序、摘要和格式转换；
- 运行支持分支、合并、局部执行、脏下游失效和停止；
- 输出节点保留完整可编辑内容，只有显式确认节点可以写入 Canon。

预设图只作为新手起点，不是能力边界。图、运行与输出都属于当前项目，可导出、可恢复。

## 5. 共享能力层

分步骤、Agent 与节点必须复用同一组能力：

```text
ContextCapability  -> CONTEXT_SOURCES / assembleContext
GenerationCapability -> 现有 adapter / GenerationNode
ValidationCapability -> schema / Canon / 时序 / 持有投影
AdoptionCapability -> FIELD_REGISTRY / AdoptionSchema / adopt
RetrievalCapability -> retrievalChunks / summary / keyword / optional embedding
```

UI 允许自由组合，不等于允许任意数据库旁路。自由发生在“选择与编排”，安全收口发生在
“读取、校验与写回”。

## 6. 当前错误实现的迁移

- 保留 Agent 右栏外壳、只读工具注册表、有界 Runner、世界来源/灵感/角色/大纲/正文候选与确认能力；
  删除前台领域标签，把三者注册为主 Agent 可调用的幕后能力。
- `PromptWorkflow` 回归分步骤线性配方；不再把 `PromptWorkflow.graph` 宣称为节点模式数据模型。
- 可复用现有 DAG 校验、拓扑排序和画布交互思想，但自由节点使用新的 `nodeFlows/nodeRuns`
  生命周期和独立工作台。

## 7. 完成判据

- 一条自然语言请求可在无领域标签的对话中调度至少两个领域能力，未确认时 Canon 零写入。
- Agent 对话、计划、输入证据与候选刷新后仍存在。
- 节点图可自由组合至少“文本 / 项目来源 / 处理 / 创作 / 校验 / 输出”六类节点。
- 作者能选择具体来源和范围，运行后逐节点查看真实输入与输出。
- 图与运行刷新、导出、导入后可恢复；旧项目和旧备份仍可打开。
- 全部工程闸门与真实 StoryForge + Agnes 浏览器闭环通过。
