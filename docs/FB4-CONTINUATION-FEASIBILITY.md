# FB-4 原稿续写可行性审查

> 状态：**设计暂缓（2026-07-25）**  
> 结论：不在当前参考作品分析上直接增加“按原作者风格续写”。IDEA-1
> 已建立可追溯来源、分析版本和持久化续跑底座，但剧情连续性胶囊等闸门仍未满足。

## 1. 用户目标与非目标

用户目标是上传一部已经完成或中断的作品，让 StoryForge 在不反复回灌整本原文的前提下，
理解结局状态、人物关系、未决线索和叙事约束，并从该状态继续创作。

本功能不应：

- 把整本原文或大量原文摘录作为每次生成的固定上下文；
- 把“写作手法分析”冒充为可依赖的剧情事实；
- 默认模仿某位作者的可识别声音；
- 在没有来源和授权记录的情况下开放续写；
- 新建一套绕开 `CONTEXT_SOURCES`、`FIELD_REGISTRY`、`ADOPTION_SCHEMAS`
  和 `PROJECT_TABLES` 的作品学习系统。

## 2. 当前代码证据

### 2.1 旧方案的地基已经不存在

历史方案指向 `src/lib/master-study/*` 和 `masterStyleMetrics`。该体系已在 DB v32
删除，当前真实入口是：

- `ReferencePanel` / `ReferenceDeepAnalysisTab`
- `reference-analysis/pipeline.ts`
- `references` / `referenceChunkAnalysis`
- `CONTEXT_SOURCES.references`

因此不能按历史文档把旧模块恢复为第二套并行业务。

### 2.2 当前分析产物不是剧情记忆

`ReferenceChunkAnalysis` 保存的是叙事、结构、节奏、人物塑造、冲突、伏笔等方法论文本。
它没有稳定、可校验的：

- 角色终态、位置、持有物与认知边界；
- 已发生事件的因果序列；
- 结局时点的世界状态；
- 已回收 / 未回收伏笔；
- 续写必须遵守的事实与明确留白。

流水线的 `rollingContext` 最多 1500 字符，只服务下一分块分析且不作为正式产物持久化。
`buildRefAnalysisContext()` 每维最多取三块的前 150 字，目标是“引用手法”，不能承担续写
Canon。现有 `analysisSummary` 同样是方法论总结。

### 2.3 长文本链路已可恢复，但剧情提取成本仍未受控

IDEA-1 已把真实解析分块按分析 run 保存到本地，支持刷新后从已完成块续跑、取消和失败重试，
同时保持旧 active 可用。但深层档位仍约每 15,000 字一块、每块最多输出 8,192 tokens；
当前 13 维方法论分析没有为剧情胶囊提供独立的阶段预算、闭集提取或聚合成本预估。不能把
剧情记忆直接叠进现有每块输出。

### 2.4 来源与分析版本地基已经完成

DB v46 的 `referenceAnalysisRuns` 已把“本人原创 / 已获授权 / 公版或明确许可 / 研究资料 /
来源待确认”、适用范围、声明时间、文件哈希和分析版本绑定；研究资料与待确认来源只能用于
分析。该声明是作者记录而非法律核验，也尚未产生可供续写选择的结构化剧情胶囊。

### 2.5 架构治理已经可用，但不能替代产品语义

GOV-1 已把参考分析 AI 写回登记到 `FIELD_REGISTRY`、`ADOPTION_SCHEMAS` 和 `adopt()`，
跨项目 FK 也有检查。普通用户 CRUD 仍由 reference store 管理。当前阻塞不是写回旁路，
而是缺少正确的数据语义、授权记录和有界剧情记忆。

## 3. 决策

当前不实现历史方案中的“按原作者风格 + 原剧情续写”入口，也不把现有方法论摘要直接接入
章节续写。AUTHOR-1 当前阶段以 EDITOR-5、FB-5 和本次可行性审查收口；FB-4 保留为
**设计暂缓**，不算功能完成。

IDEA-1 / CM-1 已完成增量素材、来源、差异预览、分析版本和失败隔离。FB-4 仍保持设计暂缓；
下一次立项应从独立的 FB-4A 连续性胶囊开始，不能把方法论报告直接接进章节生成。

## 4. 重新立项的硬闸门

FB-4 只有同时满足以下条件才可重新进入施工：

1. **来源可追溯**  
   每份材料记录来源类别、作者声明、文件哈希、声明时间和适用范围；声明变化会让旧产物
   失效，导出导入可往返。
2. **结构化剧情胶囊**  
   产物至少包含角色终态、事件因果、结局世界状态、未决线索、已回收伏笔、不可改事实和
   明确留白；必须有版本、来源块和置信/缺口信息，不能只存一段散文摘要。
3. **分层提取与本地校验**  
   分块只抽取闭集字段和逐字证据，分层合并时验证实体、顺序和来源；冲突公开给作者确认，
   AI 不得静默补齐缺失事实。
4. **有界上下文**  
   新 `CONTEXT_SOURCE` 只在作者显式选择某个胶囊时启用，预算应控制在约
   1,600–2,200 tokens；不得包含整本原文、`rawExcerpt` 集合或作者名模仿指令。
5. **声音来源分离**  
   续写默认使用作者自己的 `userStyleProfile`。参考作品只提供经过抽象的结构和连续性，
   不提供“像某作者一样写”的可识别风格仿写。
6. **成本与失败可见**  
   上传前显示预计块数和调用阶段；支持持久化断点续跑、取消和失败块重试，不能因刷新从头
   消耗。
7. **真实完成定义**  
   覆盖来源声明、产物失效、跨项目隔离、导出导入、删除级联、预算上限、冲突与缺字段反例；
   使用作者自有或合成夹具完成真实浏览器流程。

### 4.1 IDEA-1 后闸门复核（2026-07-25）

- 闸门 1 的来源、文件哈希、声明时间、适用范围和版本往返已具备；声明变更后的胶囊失效仍待
  FB-4A，因为当前没有胶囊产物。
- 闸门 6 的持久化断点、取消和失败块重试已具备；剧情胶囊专属阶段与调用预算仍未建立。
- 闸门 7 已覆盖参考分析版本的跨项目隔离、导入导出、删除级联和真实双版本浏览器流程，
  但不能代替胶囊冲突、缺字段与预算反例。
- 闸门 2、3、4、5 仍未完成。因此 FB-4 不转为 READY，也不开放任何续写入口。

## 5. 建议的后续最小阶段

在 IDEA-1 的来源与版本能力完成后，FB-4 可拆成两个独立可验收阶段：

- **FB-4A：授权作品连续性胶囊**  
  只生成、审阅、版本化和选择剧情胶囊，不生成正文。
- **FB-4B：有界接续创作**  
  复用现有章节生成节点，显式读取一个已确认胶囊 + 当前项目 Canon +
  `userStyleProfile`，先预览最终上下文和预算，再由作者触发生成。

任何阶段都不恢复旧 `master-study`，也不以“模型上下文足够大”为理由取消结构化记忆。
