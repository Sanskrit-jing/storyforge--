# WORLD-1 / Phase 35-c 外部导入词条分类设计

> 状态：已交付（2026-07-25）  
> 前置：Phase 35-b 世界知识归并已完成  
> 本阶段不改变：既有世界观、角色、大纲的分块导入语义

## 一、问题与裁决

现有大文档流水线会逐块提取世界观、角色和大纲，并立即写入项目。Codex 词条不能复用
“AI 输出数据库结构后直接写入”的方式：

- 分类是项目级实体，数据库数字 ID 不可出现在 AI 契约里；
- AI 可能误把人物、修辞或泛称识别成实体；
- 同名词条可能已有作者维护的内容，自动合并会造成静默覆盖；
- 多世界项目必须把候选固定到导入会话选择的目标世界；
- 分块会反复提到同一实体，需先跨块去重再供作者审查。

因此 Phase 35-c 采用“解析候选 → 确定性校验 → 会话暂存 → 作者审查 → `adopt()` 写回”
的五段式路径。没有作者最后确认，`codexEntries` 不发生任何写入。

## 二、AI 契约

每块解析结果可额外返回 `codexCandidates`：

```ts
interface CodexImportCandidate {
  categoryRef: string
  name: string
  summary: string
  description: string
  fields: Record<string, string>
  tags: string[]
  confidence: number
  evidence: Array<{ chunkIndex: number; quote: string }>
}
```

AI 只输出 `categoryRef`，不输出 `categoryId`、地点 ID、引用 ID 或修炼体系 ID：

- 内置分类：`builtin:<builtInKey>`；
- 自定义分类：由“领域 + 分类路径”确定性哈希生成的 `custom:<domain>:<token>`；
- 每次请求提供当前项目的紧凑分类目录和允许字段键，AI 必须从目录中选择；
- `evidenceQuote` 必须是本块原文逐字子串，否则候选在本地被丢弃；
- ref 类型字段、城池地点和修炼体系关联不由导入 AI 猜测，留给作者在词条详情中维护。

## 三、会话暂存与跨块归并

- 候选存在 `ImportSession.merged.codexCandidates`，不新增运行时业务表；
- 同一 `categoryRef + 规范化名称` 的候选跨块归并；
- 摘要、描述和普通字段保留信息更完整者，标签和逐字证据取并集；
- 滚动上下文只带候选名称，降低后续块重复输出；
- 旧会话没有候选字段时保持兼容，不需要 DB 版本迁移。

## 四、作者确认

解析报告提供“审查词条候选”入口。审查界面必须允许：

1. 逐条勾选或取消；
2. 修改词条名；
3. 把 AI 分类改为当前项目任一可用分类；
4. 修改摘要和描述；
5. 查看分类置信度与逐字证据；
6. 一次确认后再写入，取消审查不写入。

会话记录保存采纳时间与写入/跳过数量，防止误以为候选已经入库。参考资料模式可以保留
候选供以后复用，但不会自动污染当前项目。

## 五、写回与冲突策略

- 分类引用在确认时重新解析到当前项目的分类；分类已删除或改名则跳过并报告；
- 新词条通过 `adopt({ target: 'codexEntries', mode: 'add' })` 写入；
- 同分类同名已有词条时，只补作者原记录的空摘要、空描述、空结构化字段，并合并标签；
- 不覆盖既有非空文本，不自动建立 refs/FK，不把 AI 的任何数字当数据库 ID；
- 直接导入项目时固定使用会话的 `targetWorldGroupId`；从参考会话复用时由作者选择当前
  目标世界。两条路径都由现有项目边界继续校验。

## 六、完成判据

1. 非逐字证据、未知分类、非法字段在本地被拒绝；
2. 分块重复候选确定性合并，旧会话仍可加载；
3. 未确认时 Codex 零写入，确认后才通过统一采纳层落库；
4. 同名既有词条不丢作者内容，多世界不串；
5. 报告、复用会话与真实浏览器都能进入候选审查；
6. 专项测试、全量 Vitest、TypeScript、lint、build、架构与 AI Manual 门禁通过。
