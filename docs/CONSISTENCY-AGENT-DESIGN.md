# 一致性 Agent 设计（Phase 27.2c）

## 1. 产品边界

一致性 Agent 是章节编辑器中的后台只读守卫，不是第二个聊天入口，也不是自动改稿器。

- 正文保存后自动运行 `background` Fast Guard。它只复用确定性校验器，零模型调用、零 token。
- 作者可在“质量审校 → 一致性”明确运行 `fast` 或 `deep`。两者最多各调用一次模型；
  模型只负责从封闭证据中指出逐字引用，最终硬判仍由代码完成。
- `fast` 只审高置信硬边界；`deep` 才读取因果、动机、伏笔、故事线和远距召回。
- 所有结果只提示，不写正文、不改设定、不生成 adoption。

## 2. 确定性主干与模型副手

```text
保存正文
  → 正文标准化 + SHA-256
  → 确定性 Fast Guard
      └─ 当前角色持有投影 / 重复获得
  → 工具栏只显示当前正文的告警数

作者明确点检测
  → 按 fast/deep 档位装配登记上下文
  → 一次模型调用提取逐字引用
  → 引用白名单与正文/证据精确包含校验
  → 确定性认知边界、存亡时序、物品连续性判定
  → 只读报告
```

原则：

1. “是否违反已确认事实/规则”由现有 Canon 代码判断；模型与向量召回不拥有最终判权。
2. `hard` 必须有有效证据；证据丢失或不在登记上下文中时降为 `unknown` 或直接丢弃。
3. 自动后台路径不得调用模型。模型调用必须来自作者眼前的明确按钮。
4. 同一章节、同一正文 hash、同一模式不重复保存后台结果。

## 3. 上下文与预算

| 模式 | 上下文上限 | 主要来源 | 模型调用 |
|---|---:|---|---:|
| `background` | 0 | 结构化投影与确定性校验器 | 0 |
| `fast` | 16K | 连续性交接、当前事实、世界宪法、创作一致性规则、角色认知、存亡、物品、世界规则 | 1 |
| `deep` | 32K | fast + 近期摘要、远距召回、年表、关系、伏笔、故事线 | 1 |

运行保存 `included/omitted/trimmed`、输入估算、团队预算和调用次数。标准 `aiUsageLog`
仍记录提供商真实 usage；本地估算不冒充账单。

## 4. 数据与恢复

复用 `agentConversations + agentEvents`：

- 每次显式检测和有告警的后台检测写入归档 conversation；
- candidate payload 保存版本、模式、项目/章节/世界作用域、正文 hash、发现项、上下文证据和预算；
- 刷新后读取当前章最新运行；正文 hash 不同则显示“结果已过期”，不把旧告警冒充当前告警；
- 数据已由 `PROJECT_TABLES` 统一覆盖备份、导入、项目删除和级联清理。

一致性报告不是 Canon，也没有确认写回事件。

## 5. UI

- 工具栏“质量审校”在当前正文存在告警时显示计数。
- 一致性页显示：当前/过期、自动 Fast Guard 或显式 fast/deep、调用次数、token 预算、
  实际纳入/省略/裁剪来源。
- 用户可以重跑，但不能从报告直接改正文；修改仍走现有“按审校报告 AI 修改”或人工编辑路径。

## 6. 验收

- 自动保存触发的后台检查模型调用数严格为 0。
- 显式 fast/deep 每次最多 1 次模型调用，且上下文超限时显式裁剪或拒绝。
- 伪造正文 quote、伪造证据 quote、跨项目/跨世界证据和无证据 hard 均不能进入有效结果。
- 刷新恢复当前报告；正文变化后旧报告过期且工具栏不显示旧计数。
- 发现项全程只读，相关业务表在检测前后保持不变。
- 完整 `npm run ci`、Chromium E2E 与真实 Agnes 隔离项目通过。
