# AGENT-1 Phase 27.1-d · ChatCopilot 角色生成闭环

> 状态：已完成（2026-07-26）。本文只覆盖 27.1-d 的第二个独立领域闭环，不代表已有角色
> 改写、大纲、正文、泛化意图识别或多 Agent 已完成。

## 1. 开工卡

- **稳定 ID / 用户故事**：`AGENT-1-27.1-d-character`。作者在工作区副驾中描述一个新角色，
  得到可检查、可编辑的结构化角色候选；只有明确确认后才新增一条角色主档。
- **唯一归属**：AGENT-1 对话覆盖面；复用既有 `character.generate` 模板、角色维度描述符和
  `characters` 主档，不新建第二套角色数据或提示词体系。
- **入口与同步**：ChatCopilot 增加“角色生成”域；确认后重载同一个
  `useCharacterStore`，既有角色生成、主要角色、次要角色、NPC 与路人面板同步。
- **读**：只调用正式只读工具 `read_worldview` 与 `read_characters`，底层仍走
  `CONTEXT_SOURCES → assembleContext()`；不扫描章节、物品、大纲或整项目。
- **写**：候选只存在内存。确认时复用 `GenerationNode → adopt(characters, add)`；
  不直接调用 Dexie 或创建平行 store 写入。
- **表与生命周期**：不新增 schema/迁移。`characters` 已由 `PROJECT_TABLES` 覆盖项目删除、
  世界删除、导入导出、角色引用清理与 ID 重映射。

## 2. 作用域与候选契约

- 单世界项目固定写入 `homeWorldGroupId = null`。
- 多世界项目必须先选择当前世界，写入该世界；本期不创建跨世界角色。
- `projectId`、`homeWorldGroupId` 与 `isCrossWorld` 只来自可信 UI/执行作用域，模型和可编辑
  JSON 均不能提供或覆盖。
- 候选只允许 `name`、三轴、`relationships` 与 `CHARACTER_DIMENSIONS` 中的字段；
  三轴必须使用当前闭集枚举。
- 姓名和一句话简介必填；空壳、非法类型、未知字段、单字段或总 JSON 超限均由确定性代码拒绝。

## 3. 并发、重复与确认不变量

1. 生成阶段零写入；拒绝候选零写入；确认眼前候选时不再次调用模型。
2. 生成后项目角色名单或任一角色版本发生变化，旧候选拒绝写入。
3. 姓名按 Unicode NFKC、去首尾空白和不区分大小写比较；当前世界可见的同名角色
   （包括跨世界角色）会阻断，避免 `ADOPTION_SCHEMAS.characters` 的 merge 策略暗中覆盖主档。
4. 写回必须恰好新增一条角色记录；注册表跳过、类型错误或未知字段不得伪报成功。
5. 结构化候选中的关系只写既有 `characters.relationships` 文本字段，不自动创建
   `characterRelations` 边。

## 4. 本期非范围

- 不更新或补全已有角色；已有角色维度补全继续走现有角色面板。
- 不自动创建角色关系边、角色弧方案、物品流水、状态卡、事实断言、大纲或正文。
- 不创建跨世界角色，不替作者猜测种族/修炼体系等结构化外键。
- 不实现任意意图识别、聊天历史、原生 `tool_calls` 优化、多 Agent 或后台 Agent。
