# IDEA-1 / CM-1 增量灵感融合工作区

> 状态：已完成（2026-07-25）
> 范围：短灵感碎片的项目级来源、选择、增量融合、差异预览和确认版本
> 非范围：整章/整本参考正文、自动采纳 AI 结果、任意历史版本回滚、参考作品剧情记忆

## 一、问题与裁决

原“灵感反推”每次只把当前文本交给 AI，输入和结果主要保存在浏览器
`localStorage`。它能恢复单次草稿，却不能回答：

- 哪些碎片参与了本次生成；
- 碎片来自作者、参考启发还是研究资料；
- 新结果相对作者已确认版本改了什么；
- 刷新、导出、导入或删除项目后，来源和版本是否仍保持一致。

CM-1 不新建第二套生成或采纳入口，而是在原“项目 → 灵感反推”面板上增加项目级工作区：

```text
有来源的短灵感碎片
  → 作者勾选本次参与项
  → 当前已确认版本（可选、有界）
  → 既有 inspiration.reverse 生成
  → 本地闭集解析与字段差异
  → 作者确认版本
  → 既有 worldviews / storyCores / characters adopt
```

未确认结果只存在于当前预览和兼容草稿中，不写版本历史，也不能采纳到项目主档。

## 二、数据与生命周期

DB v45 新增项目级单例 `inspirationWorkspaces`：

- `fragments`：有界 `InspirationFragment[]` JSON，包含稳定碎片 ID、正文、短标题、来源类型和创建时间；
- `versions`：有界 `InspirationVersion[]` JSON，包含父版本、单/多世界模式、参与碎片 ID、闭集结果 JSON 和创建时间；
- 每项目最多 24 个碎片、12 个确认版本；单碎片最多 2000 字符；
- 已被确认版本引用的碎片是来源证据，只能取消勾选，不能删除；
- 项目删除由 `PROJECT_TABLES` 派生级联；表进入便携 JSON 导出导入；
- v45 只新增空表，不猜测迁移旧 `localStorage`。旧草稿继续可读，作者首次保存碎片或确认融合时才显式落库。

`fragments` 和 `versions` 均登记在 `FIELD_REGISTRY`，单例写回统一走
`adopt(target=inspirationWorkspaces, mode=replace)`。生成时由
`CONTEXT_SOURCES.inspirationWorkspace` 按本次碎片 ID 和模式读取，再经 `assembleContext()`
装配；未增加读写旁路。

## 三、有界输入与来源

本次只发送作者勾选的碎片。碎片按创建时间排列并标记编号、来源和标题，合计最多 9000
字符；单条超过 2000 字会在界面明确拒绝，不会静默截断。上一版已确认结果最多带入
5000 字符。未勾选碎片、其他项目数据和全部历史版本不会进入本次提示词。

提示词要求保留未被新素材否定的有效内容、吸收新增内容并显式解决冲突。碎片或上一版
结果中的指令性文字一律视为素材，不能改写任务、输出结构或安全边界。

这套边界保留项目级演化所需的关联闭包，又避免每次把全部素材和全部历史结果重复发送。
整章或整本正文仍必须走“文档解析 / 项目参考导入”，不能借 CM-1 绕过长文本流水线。

## 四、确认、差异和采纳

AI 输出先经过原单世界/多世界闭集解析。系统把上一版和新结果递归展开为字段路径，显示
最多 24 项新增、修改和删除；数组中的命名对象以名称稳定标识。

- “确认融合版本”才把结果、父版本和参与碎片写入版本历史；
- “放弃本次结果”恢复同模式的最近确认版本；
- 待确认期间，一键采纳和分区采纳均硬禁用；
- 确认后继续复用原有 `adopt()` 目标，不把灵感工作区变成第二份世界观、故事核心或角色主档；
- 单世界和多世界各自读取最近确认版本，避免结构互相覆盖。

当前仅提供最近确认版本的增量链和数量提示，不提供任意旧版本浏览/回滚。若后续增加，
必须同时处理“回滚后新分支”的父版本语义，不能只替换一个 UI 状态。

## 五、Agnes 真实验证与解析兼容

在真实项目“EDITOR-5 实体改名真实验证”中完成两轮 Agnes 调用：

1. 两个碎片（旧城遗忘规则、铜片档案）生成第一版，确认后刷新仍保留；
2. 新增“守塔人真相”，要求守塔人不是反派、失踪者改为兄妹，第二轮差异准确公开主角
   动机、守塔人身份和安全港等字段变化，确认后形成父子版本链；
3. 刷新后 3 个来源碎片和 2 个确认版本均恢复，已引用碎片不可删除，浏览器无运行时错误。

第一次真实输出使用了单引号和尾逗号，属于 JavaScript 对象字面量而非严格 JSON；后续
解析在严格 `JSON.parse` 失败时只做 JSON5 语法兼容，上层仍按闭集字段和枚举整形。
另一类模型输出会把期望字符串的字段返回为对象/数组，现统一转换为可读文本，避免
`[object Object]`。已确认历史版本不后台重写，防止静默改变作者确认内容。
