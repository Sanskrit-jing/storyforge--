# AGENT-1 Phase 27.1-d · ChatCopilot 灵感反推闭环

> 状态：已完成（2026-07-26）。本文只覆盖 27.1-d 的第一个独立领域闭环，不代表角色、
> 大纲、正文、泛化意图识别或多 Agent 已完成。

## 1. 开工卡

- **稳定 ID / 用户故事**：`AGENT-1-27.1-d-inspiration`。作者在工作区副驾中选择已有
  灵感碎片、补充本轮要求，得到可检查的结构化反推候选；只有明确确认后才保存为新的
  灵感版本。
- **唯一归属**：AGENT-1 对话覆盖面；复用 IDEA-1 / CM-1 增量灵感工作区，不新建第二套
  灵感数据或生成入口。
- **入口与同步**：ChatCopilot 增加“灵感反推”域；确认后更新同一个
  `useInspirationWorkspaceStore`，既有“项目 → 灵感反推”面板立即看到版本变化。
- **读**：新增只读工具 `read_inspiration_workspace`，只接作者明确勾选的 fragment ID，
  底层仍走 `CONTEXT_SOURCES.inspirationWorkspace → assembleContext()`；同模式最近确认
  版本由该 source 有界回注。
- **写**：候选只存在内存。确认时复用 `saveVersion → adopt(inspirationWorkspaces)`；
  不直接写 `worldviews`、`storyCores`、`characters`，这些仍由既有灵感工作台分区采纳。
- **表与生命周期**：不新增 schema/迁移。`inspirationWorkspaces` 已由 `PROJECT_TABLES`
  覆盖项目删除、便携导出导入和默认值。

## 2. 不变量

1. 模型参数不能提供或覆盖 `projectId`；fragment ID 必须属于当前项目工作区。
2. 未勾选碎片不进入模型输入；空选择在 API 调用前阻断。
3. 候选必须通过单/多世界结构解析、非空价值和 40K 结果上限。
4. 拒绝候选零写入；确认不再次调用模型。
5. 生成后工作区发生变化时，旧候选拒绝写入，防止覆盖并发版本或引用失效来源。
6. 多世界项目只改变反推结果模式，不把单个世界作用域冒充整个项目灵感作用域。

## 3. 本期非范围

- 不把用户聊天自动保存为灵感碎片；新增来源仍走现有“加入素材库”明确动作。
- 不实现任意意图识别、角色/大纲/正文对话生成、聊天历史或原生 `tool_calls` 优化。
- 不实现多 Agent、后台整理本章、一致性 Agent、NPC 演进或 per-role 模型。
- 不把整章、整本或参考原文塞进灵感输入；长材料继续走文档解析与项目参考导入。

## 4. 验收

- 工具参数、跨项目碎片、空选择、预算与零写入有反例测试。
- 单世界与多世界候选均可解析；空壳、超限、过期候选阻断。
- UI 可选择碎片、查看/编辑结构化候选、拒绝或确认；确认后版本数和既有面板同步。
- Playwright 真实项目验证：拒绝零写入；确认只新增一个版本且不二次调用模型。
- 完整 `npm run ci`、`npm run ci:e2e`、`git diff --check` 通过。

## 5. 完成证据

- `R-AGENT1-read-tool-registry`：工具集合、只读零写入、空选择、混入跨项目 ID、项目模式
  不一致和仅选中来源均有正反例。
- `R-AGENT1-chat-copilot-inspiration`：单/多世界解析、内存候选、编辑后精确确认、空壳
  gate、并发过期、非法 JSON 和跨项目选择均有回归。
- `R-AGENT1-chat-copilot-ui`：双领域切换、来源展示、差异摘要、可见 JSON 编辑与独立
  拒绝/保存动作均有组件回归。
- Chromium E2E 在隔离项目中验证“保存碎片 → 生成 → 拒绝仍为 0 版 → 再生成 → 编辑
  JSON → 确认变为 1 版 → 项目主档无写入”，两次确认阶段均无额外模型调用。
- 当前 Agnes 配置在临时项目中返回真实结构化候选；非严格 JSON 由既有 JSON5 兼容层
  恢复，作者编辑标记逐字进入确认版本，世界来源主档保持空白；临时项目随后完整清理。
