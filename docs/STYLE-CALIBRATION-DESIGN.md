# FB-5 高级文风校准设计

> 状态：完成（2026-07-25）
> 主归属：AUTHOR-1
> 前置：FB-5 基础画像、EDITOR-3 对照润色
> 非范围：个人向量库、整本原稿续写、未经作者确认的自动学习

## 1. 用户闭环

FB-5 高级阶段把“已有章节总结画像”扩展为两条相互补充、但仍由作者掌控的路径：

1. 作者在章节的“对照润色”中保存实际改稿，系统只截取变化附近的短片段，沉淀一组“改前 / 改后”样本。
2. 作者在“文风学习”中查看、注释或删除样本，并可重新生成文风画像。
3. 已有画像时，作者可粘贴一段不超过 1600 字符的短文，执行“重写 → 人工编辑 → 判断 → 显式保存样本”。
4. 下游章节生成继续只读取登记的 `userStyleProfile` 上下文源；画像、最多三组短样本和最近反馈共同进入上下文。

AI 生成的校准稿不会自动成为训练样本。只有作者点击“保存为改稿样本”后才落库，避免模型自己的输出循环污染画像。

## 2. 数据模型与兼容

继续使用每项目单例表 `userStyleProfiles`，增加两个非索引、可选 JSON 字段：

- `revisionPairs`：最多 8 个 `StyleRevisionPair`。
- `calibrationFeedback`：最多 12 个 `StyleCalibrationFeedback`。

字段是现有记录的可选扩展，不改变索引、主键或表结构，因此不增加 Dexie schema 版本。旧项目缺少字段时按空数组读取；现有 `PROJECT_TABLES` 生命周期、项目导出导入、删除级联自动覆盖新增字段。

“先改稿、后画像”会创建一个 `profile=''`、`enabled=false` 的安全空壳记录。首次真正生成画像时自动开启注入；已有非空画像则保留作者原来的开关选择。

## 3. 输入成本护栏

本阶段不引入向量数据库。当前数据量下，精确的有界样本比新建检索基础设施更简单、可解释：

- 画像学习一次最多读取 6 章。
- 每章先转纯文本，再最多取 2500 字符。
- 改稿样本只保存共同前后缀之外的变化区域及少量上下文，每侧最多约 560 字符。
- 项目最多保存 8 组样本；上下文和 Prompt 最多选 3 组。
- 带作者说明的样本优先，其次按时间从新到旧。
- 互动校准原文最多 1600 字符；反馈上下文只注入结论与短说明，不重复注入原稿和结果全文。

这些上限控制的是重复输入，不牺牲项目级风格画像。未来只有在样本规模和按场景检索的收益得到真实数据证明后，才评估个人写作向量库。

## 4. 改稿样本提取

`src/lib/style/style-learning.ts` 负责纯函数：

1. HTML 转纯文本并规范空白。
2. 计算改前、改后的最长公共前缀和后缀。
3. 围绕真实变化范围截取有界上下文。
4. 以来源章节和内容稳定哈希去重。
5. 按作者说明优先级和时间选择最多三组 few-shot。

完全相同、任一侧为空的正文不会生成样本。对照润色正文和快照成功后再尝试沉淀样本；样本写入属于衍生数据，失败只记录警告，不能回滚已经成功保存的章节。

## 5. AI 与注册表边界

- `style.learn`：分析任务。章节样本、改稿对照和校准反馈共同产出可手改画像。
- `style.calibrate`：创作任务。只在保留事实、视角、顺序和信息量的前提下改写短文。
- `userStyleProfile`：唯一的下游读取源，预算由 700 提高到 1800 token，以容纳画像和三组有界样本。

Prompt 明确禁止复制样本的剧情、人物名、地点名和专有名词。没有非空画像或作者关闭注入时，样本和反馈也不会单独进入下游上下文。

本阶段没有新表、没有新的 `ADOPTION_SCHEMA`，也没有面板内直接拼接下游上下文。持久化继续由 `useUserStyleStore` 负责，上下文只由 `CONTEXT_SOURCES` 装配。

## 6. 失败与安全边界

- 文风样本沉淀失败不回滚正文和恢复快照。
- 校准 API 失败不落反馈、不落样本。
- 删除样本不会修改历史正文或已生成画像；作者需要点击“重新学习”才会更新画像。
- 关闭画像后，画像、样本和反馈全部停止注入。
- 样本只包含短摘录，不保存新的整章副本。
- 对照润色在 React 严格模式下切换单/双编辑器时，必须拒绝访问已销毁的 TipTap 实例。

## 7. FB-4 复用与非范围

FB-4“原稿续写”可复用本阶段的：

- 可解释 Style Card；
- `style.learn` 的对照学习原则；
- 有界 few-shot 格式；
- 创作任务模型路由；
- 登记上下文源和输入预算护栏。

FB-4 仍需独立设计剧情记忆、版权/授权提示、原稿来源、长文本提取和成本预估。不得把整本原稿塞进 `userStyleProfiles`，也不得以本阶段完成为由直接开启整本回灌。

## 8. 验证

- `R-FB5-advanced-style`：差异截取、上限、去重、优先级、空画像、反馈和上下文约束。
- `R-FB5-style-profile`：画像、样本和反馈的导出导入及删除生命周期。
- `R-FB5-style-calibration-ui`：真实 React 交互的生成、人工编辑、反馈与显式保存。
- `R-EDITOR3-rich-editor-lifecycle`：严格模式下单编辑器切双栏对照。
- Playwright：真实建卷建章、对照润色、样本沉淀、画像学习、互动校准、刷新恢复。
